# Route matrix: route -> screen -> action -> service -> permission -> test

Written 2026-10-18. Paths are relative to the application root (`claude-code-chasis-v1/app/`); route files live in its `app/` directory. The 31 patterns are those of `../rutas-y-pantallas.json`; each page file listed below exists (checked while generating this file).

How to read it:

- **Contract actions** are the `primary_actions` of the route in `rutas-y-pantallas.json`. **Server service / action** lists what the page and its components actually import or call; an action named in the contract but absent from that column has no wiring found (see `IMPLEMENTATION_STATUS.md` section 7, item 6).
- **Permission**: every `/a/:agencySlug/...` page first resolves the signed-in member of that agency (`requireAgency`); the extra permission names are from `lib/policy.ts` and `lib/capabilities/governance.ts`. Components hide a control the role lacks, and the server action re-checks it.
- **Vitest** files ran in the full suite (38 files, 913/913 passed, coordinator, 2026-10-18). **Browser spec** names the Playwright test; the specs have not produced a certified result yet, so **Browser result** is `<<E2E_PENDING>>` on every row. The earlier read-only run (45 passed, 14 failed, 16 skipped) is superseded.
- Playwright specs (`tests/e2e/`): the `routes.spec.ts` crawl tests are titled `<route id> <path>`. `routes.spec.ts` crawls all 31 patterns with real params and asserts HTTP < 400, no error overlay, a visible h1, no placeholder copy and no uncaught page errors; it also asserts the contract has exactly 31 patterns, that the agency owner gets 404 on `/ops*`, and that Norte deep links under Rayo resolve to not-found.
